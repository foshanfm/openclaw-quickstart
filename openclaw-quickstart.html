Phase 1: 安装 OpenClaw

3 步 ~3 分钟
1打开终端（命令行）

终端是一个可以输入文字命令的窗口，所有安装和配置操作都在这里完成。

macOS：按 Command + 空格，输入 Terminal（终端），回车打开。
也可以打开"访达" → "应用程序" → "实用工具" → 双击"终端"。

Windows：按 Win 键，输入 PowerShell，点击打开。
或右键开始菜单选择"Windows PowerShell"。

Linux：按 Ctrl + Alt + T（大多数发行版通用）。

打开后你会看到一个黑色/白色的窗口，里面有闪烁的光标 — 这就是终端。接下来的命令都在这里输入。

已打开终端
2一键安装

复制下面的命令，粘贴到终端中，按回车执行：

macOS / Linux：安装脚本会自动检测系统、安装 Node.js（如果没有）、安装 OpenClaw、并启动引导向导。
curl -fsSL https://openclaw.ai/install.sh | bash

Windows 用户：在 PowerShell 中运行：

iwr -useb https://openclaw.ai/install.ps1 | iex

脚本运行完成后会自动进入引导向导，按提示选择模型、输入 API Key 即可。引导向导会在 Phase 2 详细说明。

▶ 想手动分步安装？

如果一键脚本遇到问题，可以手动操作：

1. 安装 Node.js（需要 v22.16+ 或 v24）

推荐用 nvm（免 sudo 权限问题）：

curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash

重启终端后：

nvm install --lts

或直接从 nodejs.org 下载 LTS 安装包，双击安装。

2. 安装 OpenClaw

npm install -g openclaw@latest

3. 运行引导向导

openclaw onboard --install-daemon
安装完成，进入引导向导
3验证安装

安装完成后，在终端中运行以下命令确认：

openclaw --version

预期输出: openclaw 2026.x.x

openclaw doctor

这个命令会自动检查配置是否有问题。看到绿色提示即表示一切正常。

验证通过

Phase 2: 配置 AI 模型

6 步 ~8 分钟
1了解配置文件

OpenClaw 的配置存储在 ~/.openclaw/openclaw.json，核心配置包括模型提供商和 Gateway 设置。

▶ 查看配置文件结构示例
{ "models": { "providers": { "minimax": { "baseUrl": "https://api.minimaxi.com/anthropic", "api": "anthropic-messages" } } }, "agents": { "defaults": { "model": { "primary": "minimax/MiniMax-M2.7" } } }, "gateway": { "port": 18789, "bind": "loopback" } }
了解配置文件位置
2获取 API Key

选择一个模型提供商，注册并获取 API Key：

提供商推荐模型注册链接
MiniMaxMiniMax-M2.7platform.minimaxi.com
DeepSeekDeepSeek-V3platform.deepseek.com
DashScopeQwen-Maxdashscope.aliyun.com
OpenAIGPT-4oplatform.openai.com

注册后在 API Keys 页面创建新 Key 并复制保存。

已获取 API Key
3运行安装向导

OpenClaw 内置引导式安装向导，会自动完成配置和 Gateway 安装：

openclaw onboard --install-daemon

向导会依次引导你：选择模型提供商 → 输入 API Key → 设置 Gateway → 安装后台服务。全程按提示操作即可，无需手动编辑配置文件。

▶ 手动编辑配置（高级）

也可以直接编辑 ~/.openclaw/openclaw.json，以下为 MiniMax 模板：

{ "models": { "mode": "merge", "providers": { "minimax": { "baseUrl": "https://api.minimaxi.com/anthropic", "models": [], "api": "anthropic-messages", "authHeader": true } } }, "agents": { "defaults": { "model": { "primary": "minimax/MiniMax-M2.7" } } } }
注意：contextWindow 字段必须手动填写，否则 OpenClaw 默认使用 16K 上下文，会导致 AI 回答质量下降。
配置向导完成
4验证 Gateway 运行

安装向导已自动启动 Gateway 后台服务。验证运行状态：

openclaw status
打开浏览器访问 http://localhost:18789，你应该能看到 OpenClaw 的控制面板。
Gateway 启动成功
5添加更多模型（可选）

OpenClaw 支持同时配置多个模型提供商，随时切换。编辑 ~/.openclaw/openclaw.json：

▶ 查看多模型配置示例
{ "models": { "mode": "merge", "providers": { "minimax": { "baseUrl": "https://api.minimaxi.com/anthropic", "api": "anthropic-messages", "authHeader": true }, "deepseek": { "baseUrl": "https://api.deepseek.com/anthropic", "api": "anthropic-messages" }, "dashscope": { "baseUrl": "https://dashscope.aliyuncs.com/compatible-mode/v1", "api": "openai-chat" } } }, "agents": { "defaults": { "model": { "primary": "minimax/MiniMax-M2.7" } } } }

切换默认模型：修改 agents.defaults.model.primary 的值，格式为 provider/model-name

提供商模型名称primary 值
MiniMaxMiniMax-M2.7minimax/MiniMax-M2.7
DeepSeekDeepSeek-V3deepseek/DeepSeek-V3
DashScopeQwen-Maxdashscope/qwen-max
OpenAIGPT-4oopenai/gpt-4o

修改配置后重启 Gateway 生效：openclaw gateway restart

6配置网络代理（如需翻墙）

如果你使用代理软件（如 Clash Verge、V2Ray 等）访问海外 API，需要让 OpenClaw 的流量也走代理。

为什么需要配置？OpenClaw 的 Gateway 进程不会自动读取系统代理设置。即使你的浏览器能正常访问 API，Gateway 仍然可能直连导致超时或报错。

方法一：CLI 命令配置（推荐）

Clash Verge 默认 HTTP 代理端口为 7890，请根据你的实际端口调整：

openclaw config set proxy.enabled true openclaw config set proxy.proxyUrl http://127.0.0.1:7890 openclaw gateway restart

方法二：环境变量

export OPENCLAW_PROXY_URL=http://127.0.0.1:7890 openclaw gateway run

方法三：写入配置文件

编辑 ~/.openclaw/openclaw.json，添加 proxy 字段：

{ "proxy": { "enabled": true, "proxyUrl": "http://127.0.0.1:7890", "loopbackMode": "gateway-only" }, "models": { ... }, "agents": { ... } }

验证代理是否生效：

openclaw proxy validate --proxy-url http://127.0.0.1:7890

看到 ok: true 即表示代理配置正确。

注意事项：
• 代理 URL 必须用 http://，不能用 https://
• 仅支持 HTTP 正向代理，不支持 SOCKS 代理
• Clash Verge 同时提供 HTTP 和 SOCKS 端口，使用 HTTP 那个（默认 7890）
• loopbackMode: gateway-only（默认）让本地 Gateway 流量直连不走代理，推荐保留
▶ 代理配置后仍然连不上？

1. 确认 Clash Verge 正在运行，且系统代理已开启

2. 确认端口号正确：打开 Clash Verge → 设置 → 查看 HTTP 代理端口

3. 手动测试代理连通性：

curl -x http://127.0.0.1:7890 https://api.openai.com

4. 如果 Clash Verge 开了"系统代理"模式，尝试改为"规则"模式

5. 检查是否有 no_proxy 环境变量干扰：

echo $HTTP_PROXY $HTTPS_PROXY $no_proxy
代理配置完成（或不需要代理）

Phase 3: 第一个任务 — 整理桌面文件

4 步 ~5 分钟
1备份桌面
重要：在让 AI 操作文件之前，建议先备份桌面。OpenClaw 会直接在你的文件系统上执行操作。

运行以下命令创建桌面备份：

cp -r ~/Desktop ~/Desktop-backup-$(date +%Y%m%d)
已备份桌面
2发送整理指令

在 OpenClaw 的对话界面（Web UI 或微信）中，发送以下指令：

请帮我整理桌面文件，按照文件名称和内容分类到不同文件夹

如果想要更精确的控制，可以使用详细版：

请扫描 ~/Desktop 目录下的所有文件，根据文件名称和内容将它们分类到不同文件夹中。例如：工作文档、个人文件、图片、视频、安装包等。请先列出你的分类计划，确认后再执行。
已发送整理指令

常见问题

npm install 报错 EACCES 权限问题▼
这是 npm 全局安装权限问题。解决方案：
1. macOS/Linux: 在命令前加 sudo：sudo npm install -g openclaw
2. 或修复 npm 权限：mkdir ~/.npm-global，然后配置 npm 使用该目录。
3. 推荐使用 nvm 管理 Node.js 版本，可避免权限问题。
openclaw: command not found▼
npm 全局安装路径不在系统 PATH 中。
1. 运行 npm root -g 查看全局安装路径
2. 将该路径的上级 bin 目录添加到 PATH
3. 或使用 nvm 重新安装 Node.js
Gateway 启动失败，端口被占用▼
默认端口 18789 被其他程序占用。
1. 查看占用端口的进程：lsof -i :18789
2. 停止该进程或修改 OpenClaw 配置中的端口号
3. 重启 Gateway：openclaw gateway restart
API 调用失败 / 模型无响应▼
1. 检查 API Key 是否正确配置
2. 确认 API 账户有余额
3. 检查网络连接，某些模型提供商需要稳定网络
4. 如果使用代理，确认代理已正确配置（见 Phase 2 Step 6）
5. 查看日志排查：openclaw logs | grep -i error
使用 Clash/V2Ray 代理后 API 仍然超时▼
OpenClaw 不会自动读取系统代理，需要手动配置：
1. 确认已按 Phase 2 Step 6 配置了 proxy.proxyUrl
2. 代理 URL 必须是 http://（不是 https://），端口用 HTTP 代理端口（非 SOCKS）
3. 验证代理连通性：openclaw proxy validate --proxy-url http://127.0.0.1:7890
4. 检查代理软件是否开启了"系统代理"模式，尝试切换为"规则"模式
5. 手动测试：curl -x http://127.0.0.1:7890 https://api.openai.com
代理配置后本地 Gateway 也走代理了，变慢了▼
默认 loopbackMode: gateway-only 应该让本地 Gateway 流量直连。如果仍然走代理：
1. 确认配置中 proxy.loopbackMode 设为 gateway-only（默认值）
2. 检查是否有 GLOBAL_AGENT_NO_PROXY 等环境变量冲突
3. 重启 Gateway 使配置生效：openclaw gateway restart
文件整理时 AI 没有按预期分类▼
1. 尝试给出更具体的指令，明确分类规则
2. 要求 AI 先列出分类计划，确认后再执行
3. 如果结果不满意，可以逐个调整："请把 X 移到 Y 文件夹"
4. 备份目录始终可用，随时可以恢复
如何更换或添加其他 AI 模型？▼
编辑 ~/.openclaw/openclaw.json：
1. 在 models.providers 中添加新的提供商配置（需要 baseUrl 和 api 类型）
2. 修改 agents.defaults.model.primary 的值为目标模型，格式为 provider/model-name
3. 重启 Gateway：openclaw gateway restart
详见 Phase 2 的 Step 5 说明。
看到 "Compacting context..." 是什么意思▼
这是 OpenClaw 在压缩对话上下文。当对话过长超出模型上下文窗口时会自动触发。
1. 不影响正常使用，是正常行为
2. 如果频繁出现，可在配置中增大 contextWindow 值
3. 建议定期开始新对话以保持最佳体验
